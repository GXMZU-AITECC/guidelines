# D · 权限管理规则

## D1 角色与权限（管理员执行，对应 T0）

按 GitHub 上的实际层级分 4 档，一个人可以同时在高的一档：

| 层级 | team | 权限范围 |
| --- | --- | --- |
| 组织管理员 | — | 组织全部设置、建仓删仓、建 team、指派 Reviewer；对全部仓库有管理员权限 |
| 项目负责人 | 项目 team（如 `unitree-go2`、`yundrone`、`zhilian-cyber`） | 本项目仓可写、可合并 PR；只管自己这一个仓 |
| 评审人 Reviewer | `reviewers` | 训练场 PR 可批准、可合并；其余仓库按被拉进的 team 定 |
| 新人 Rookies | `rookies` | 训练场、`qq-auto-bot`、非比赛研发项目（`unitree-g1-demo`）与成员主页只读；提 PR 靠 fork |

- 组织默认仓库权限为 `none`：**没有任何"因为入社了就全都能看"这回事**，能看见什么完全取决于进了哪个 team。
- 比赛项目（智能车 `zhilian-cyber`）只有 Reviewer 及以上可选加入。

## D2 权限申请（管理员执行）

1. 新人通过训练场考核 → 管理员拉进 `rookies`；
2. 要进某个项目 → 找该项目负责人，由负责人报管理员把你加进那个项目 team；
3. Reviewer 由社长手动指派，不接受自荐；
4. 校外合作者（如有）只在指定仓库挂外部协作者，不给组织成员身份。
## D3 内部资产与保密（→ P0）

组织下所有仓库的内容（源码、文档、Issue 与 PR 讨论、任务池等）均为**社团内部资产**，无论仓库技术上是否对外可见；面试考核期间获取的内容同样适用。

- **D3-1** 不得将仓库内容以任何形式（链接、截图、复制、转发）泄露给组织外人员；
- **D3-2** 发现泄露或违规行为，上报**人工智能学院指导教师**处理；对于泄露人本科期间学业所产生的负面潜在影响，均由泄露人自负。本社团绝不姑息此类行为，亦不承担连带责任，并保留社团级别的继续追责权利。特此声明！
